# 09 — Risk Register

Likelihood (L) and impact (I) on a 1–3 scale; exposure = L × I. Each risk has a **measurable alert threshold**, a named **owner**, and the action taken when the threshold is crossed. It is reviewed at every milestone.

## Top three risks (for the M1 review)

1. **RK-04 Prompt injection** — the attack surface is the main input (the SRS itself). Threshold: any fixture changes rule findings or auto-accepts an item. Owner: Omar.
2. **RK-01 Schema failures** — batched calls (ADR-003) make one bad response cost a whole stage. Threshold: > 5% of calls over 20 runs. Owner: Thabit.
3. **RK-03 Non-determinism and model drift** — DevAI's model name is already retired upstream and silently remapped to V4.1-Flash. Threshold: Jaccard < 0.80 over 5 runs. Owner: Omar.

## Coherence notes

- Every accepted downside in an ADR has a matching risk: ADR-001 → RK-06; ADR-002 → RK-02; ADR-003 → RK-01, RK-05; ADR-004 → RK-08.
- The coupling report's residual risk (prompt and schema coupling) is monitored through RK-01 and RK-08, because schema failures and drop-rate spikes are its observable symptoms.
